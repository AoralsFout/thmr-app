# 统一 THMR 桌面客户端实施计划

开始日期：2026-11-09。工作分支：`codex/unified-cli-tui-gui`，基于上游 `f96e76b`。

## 目标与约束

- 同一仓库维护 Flutter GUI、Rust CLI/TUI 和独立桌面播放宿主 `thmrd`。
- 桌面三个入口共享一个音频引擎、播放状态和系统媒体会话；移动端保留原生应用内播放。
- 首版交付免登录直播、来源/码率/音量设置、状态查询、TUI、GUI 接入和两类桌面安装包。
- 登录桥接、收藏、纯终端授权属于后续里程碑，不能阻塞免登录收听版本。
- 保留当前 Flutter 目录结构和旧客户端更新协议；统一产品版本，独立协商本机协议版本。
- 不提供点播、seek 或管理员跳歌；恢复播放连接直播边缘。

## 分阶段执行

每阶段完成适当验证后提交；集成阶段推送 fork，执行 PR/手动预览构建。稳定标签和正式发布等待整体验收。

### P1：工程与协议基础

- [ ] Cargo workspace、固定工具链、依赖锁和统一版本注入。
- [ ] 版本化命令、快照、会话实例 ID、状态 revision 和能力协商。
- [ ] 用户级运行目录、独占锁、认证实例发现与配置持久化。
- [ ] 协议/设置错误及兼容性测试。

### P2：播放宿主与 CLI

- [ ] libmpv 后端；加载、停止、音量、事件与退出资源释放。
- [ ] 单所有者播放状态机：暂停意图、重试上限、迟到事件处理。
- [ ] Radio 状态轮询、换曲刷新、元数据、来源和启用码率。
- [ ] 认证 loopback HTTP/WebSocket；断线重订阅完整快照。
- [ ] CLI 命令、后台启动、状态 JSON、诊断和 GUI 启动。
- [ ] Windows/macOS/Linux 系统媒体集成和原生宿主生命周期。
- [ ] 本地假流与真实服务的有界播放验证。

### P3：TUI 与 Flutter 接入

- [ ] TUI：状态/曲目/排播/来源/码率/音量，键盘操作与终端恢复。
- [ ] Flutter 桌面 daemon adapter：命令、快照、重连与元数据。
- [ ] 桌面禁用本地 Player、重复状态轮询和重复媒体注册；移动端不受影响。
- [ ] 来源、码率、音量统一归宿主；主题/窗口设置继续归 GUI。
- [ ] 验证同时启动、界面关闭、宿主重启与用户暂停后的网络恢复。

### P4：构建与发行

- [ ] 保留现有 GUI 产物名称，增加独立终端包。
- [ ] 原生平台构建 Rust，完整桌面包捆绑 CLI/宿主；固定音频依赖来源。
- [ ] PR 验证 Rust/Flutter/协议/打包；非发布分支不发布稳定更新。
- [ ] 同一产品版本/构建号、校验和、依赖说明与签名验证。
- [ ] 更新事务停止整套桌面进程；兼容旧 GUI 清单，终端包独立更新策略。
- [ ] 三平台 CI 构建与可执行冒烟，记录真实媒体键验收的范围。

## 发布形态

完整桌面包：Flutter GUI + `thmr`（CLI/TUI）+ `thmrd` + 平台音频依赖。

终端包：`thmr` + `thmrd` + 必要音频依赖，无 Flutter。首期使用压缩包和手动升级；包管理器版本由包管理器更新。

Windows x64、Linux x64、macOS arm64/x64 首期优先。macOS 完整包沿用通用应用；终端包可分架构。Android 沿用 APK，iOS 不通过桌面自更新器更新。

## 验收标准

1. TUI 和 GUI 并发启动只有一个播放宿主和音频连接。
2. 系统媒体键、CLI、TUI、GUI 的播放暂停状态一致。
3. 关闭界面保留播放；明确停止/退出后关闭音频并释放资源。
4. 暂停期间断网恢复、切来源或换码率不自动播放。
5. 状态请求失败不打断正常音频；重试到上限后可主动恢复。
6. 不兼容协议明确报错，不静默生成第二个播放器。
7. Windows 实测；Linux/macOS 在原生 CI 构建并运行可自动化检查，物理媒体键另行记录。
