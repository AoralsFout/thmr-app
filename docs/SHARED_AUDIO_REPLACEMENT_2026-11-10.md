# 正式替换：共享 PCM、播放时钟指标与前后实测

**已把单连接方案接入正式 `thmrd` 和 TUI，并更新本地 Debug 二进制。** 不再是原型进程：正式宿主负责一次 MP3 解码、共享 PCM、有界提前分析和按实际播放位置取用指标；正式 TUI 经鉴权的本地通道接收已到期指标。

本次正式复测覆盖两个真实音源、6 个播放代次，共采集 **241.44 秒**音频，得到 **100 个可靠匹配片段**。合并后的“系统音频输出 → 舞台帧提交”时差中位数 **22.47 ms**，P95 **39.67 ms**，最小/最大为 3.70 / 50.67 ms。暂停恢复、切换音源后没有再观察到原先数百毫秒的持续偏移。

## 前后差异

正数表示舞台帧提交比对应系统音频输出晚，负数表示提前。全部使用 FFT 窗口末端口径。

| 实现 / 场景 | 有效片段 | 时差中位数 | P5–P95 |
| --- | ---: | ---: | ---: |
| 替换前，音源 1，新基线 | 20 | −795.0 ms | −811.7～−783.1 ms |
| 替换前，音源 1，同方式复测 | 32 | +640.1 ms | −826.1～+665.1 ms |
| 验证原型，音源 1 | 27 | +20.2 ms | +12.2～+129.4 ms |
| 验证原型，音源 2 | 32 | +18.5 ms | +8.7～+78.1 ms |
| **正式实现，音源 1** | **31** | **+22.0 ms** | **+6.7～+35.3 ms** |
| **正式实现，音源 2** | **31** | **+23.3 ms** | **+10.3～+40.7 ms** |

旧实现第二轮在同一次连接中从提前约 0.8 秒变成滞后约 0.6 秒。该轮绝对误差中位数约 658.7 ms，绝对误差 P95 约 826.1 ms；第一轮绝对误差中位数约 795.0 ms。正式实现保留了与原型相近的对齐效果，并已包含独立宿主、真实本地 WebSocket 和正式 TUI 的传输开销。

| 方面 | 替换前 | 正式实现 |
| --- | --- | --- |
| 播放与分析的直播请求 | 两条独立请求 | 每个播放代次一条共享请求 |
| MP3 解码 | libmpv 播放解码 + TUI 分析解码 | 宿主 minimp3 解码一次，共用同一份 PCM |
| 指标推进依据 | 分析端独立 sleep，停顿后平移时间基准 | 宿主实际 `audio-pts` 与样本位置 |
| 缓冲数据 | 两端各自缓冲 | 有界 PCM 与带位置的提前分析队列 |
| 暂停 / 重连 / 切换 | 分析与播放分别建立内容基准 | 作废旧代次，清除旧指标，重新加入直播位置 |
| TUI 网络 | 请求电台流 + 本地控制 | 仅本地控制和本地指标订阅 |

这里的一条连接指播放与分析共用的音频请求。元数据请求、自动音源选择和显式测速仍按原有功能运行，测速可能短暂产生匿名探测流；本次真实量测显式选择音源，没有运行自动测速。

## 宿主调度、提前量与回收

| 正式场景 | 宿主取用指标的时差中位数 / P95 | 指标提前计算量中位数 | 分析领先峰值 | 已回收指标 |
| --- | ---: | ---: | ---: | ---: |
| 音源 1 | 5.69 / 14.74 ms | 1770 ms | 2.391 s | 2869 |
| 音源 2 | 6.39 / 17.95 ms | 636 ms | 1.312 s | 2856 |

两轮各只有一次上游播放请求。指标队列峰值分别为 93、52 条；应用 PCM 队列峰值分别为 340992、129024 字节。队列随播放消费并回收，不随运行时间累积。上限是三秒加最多一个 MP3 帧，已经由队列回归和实际量测共同检查。

宿主先选指标、TUI 再接收和绘制，因此两种时差不同。终端绘制依然可能受负载影响，本次正常两轮帧提交间隔中位数均约 46.7 ms。共享时钟解决内容位置错位，不等于物理显示零延迟。

## 真实暂停恢复和音源切换

连续运行 100 秒，约第 20 秒暂停、第 22 秒恢复、第 45 秒从音源 1 切到音源 2、第 70 秒再次暂停、第 72 秒恢复。采到约 91.93 秒音频，其余时间包括暂停和重新连接的无输出阶段。

| 音频代次 | 场景 | 有效片段 | 帧提交时差中位数 / P95 | 上游请求 |
| --- | --- | ---: | ---: | ---: |
| 1 | 初始音源 1 | 5 | 22.43 / 40.94 ms | 1 |
| 3 | 第一次暂停后恢复，重新加入直播 | 10 | 22.25 / 37.33 ms | 1 |
| 4 | 切换到音源 2 | 11 | 27.17 / 43.17 ms | 1 |
| 6 | 第二次暂停后恢复 | 12 | 20.31 / 37.38 ms | 1 |

代次 2、5 是暂停状态，没有可用于播放的旧指标。客户端另外记录了全部音频帧，未发现 `feature.endSample > playbackSample`。真实直播的这轮验证覆盖保留现有“暂停停止下载、恢复加入直播边缘”的正式语义，与之前原型保留连接的暂停实验不同。

完整断流与自动重连还通过本地夹具验证：真实宿主、计时 libmpv 空输出、两个本地 MP3 服务，检查了 44.1 kHz 双声道切换到 48 kHz 单声道、码率切换、主动断开服务器连接、退避重连、旧指标清除与新样本时钟。此项没有对公网直播服务器注入故障。

## 资源观测与代价

以下为 Debug 构建、开启本地测量记录时的观测。CPU 数值以一个逻辑核心为 100%；驻留集是进程 Working Set，不是独占物理内存。

| 进程 | 替换前 CPU / 驻留集中位数 | 正式音源 1 CPU / 驻留集中位数 | 正式音源 2 CPU / 驻留集中位数 |
| --- | ---: | ---: | ---: |
| 宿主 | 6.47% / 40.00 MiB | 14.42% / 53.29 MiB | 15.39% / 52.65 MiB |
| TUI | 19.53% / 27.11 MiB | 15.48% / 24.07 MiB | 16.00% / 24.44 MiB |

分析计算迁入宿主，TUI 资源下降，宿主资源增加；本次总 CPU 和驻留集没有降低。正式量测还额外订阅了一条本地指标通道用于验证，宿主 CPU 包含该诊断订阅的序列化开销；录音和逐帧记录也有开销。旧基线起播阶段曾与增量编译重叠，CPU 频率、后台负载、音乐内容和弹幕会话种子没有锁定。因此这些资源数值用于揭示代价，不能视为严格 A/B 性能结论，更不能代替 Release 测量。

## 实现落点

- [`crates/thmr-core/src/audio`](../crates/thmr-core/src/audio/mod.rs)：共享指标类型、原有 FFT/音乐特征及频谱映射；带位置的音频帧验证。
- [`crates/thmr-daemon/src/audio`](../crates/thmr-daemon/src/audio/mod.rs)：唯一直播请求、native MP3 解码、共享 PCM、有界提前分析、取消与回收。解码器现在只链接进宿主。
- [`crates/thmr-daemon/src/mpv.rs`](../crates/thmr-daemon/src/mpv.rs)：内存 PCM 输入、动态采样格式、播放时钟和安全取消回调。
- [`crates/thmr-daemon/src/session.rs`](../crates/thmr-daemon/src/session.rs)：音频代次和播放状态机，每 20 ms 调度到期指标。
- [`crates/thmr-daemon/src/server.rs`](../crates/thmr-daemon/src/server.rs)：经过原有鉴权及浏览器访问限制的 `/v1/audio` 通道。
- [`crates/thmr-cli/src/tui/spectrum.rs`](../crates/thmr-cli/src/tui/spectrum.rs)：只订阅本地指标；保留断流时事件基准，恢复时不补发旧节拍。
- [本地协议](../protocol/README.md)、[终端说明](TERMINAL.md)、[开发说明](DEVELOPMENT.md)已更新。控制协议仍为版本 1，新指标消息使用独立 `audioVersion: 1` 与 `capabilities.syncedAudio`，旧 GUI 控制协议保持兼容。

新 TUI 发现旧宿主不支持同步指标时会提示重启或升级，不会退回第二条直播连接。旧版本 TUI 本身仍需与宿主一起升级，才会使用新指标通道。

测量入口为 [`tool/measure_host_audio.py`](../tool/measure_host_audio.py)，使用正常二进制，不拼接原型舞台。Windows CPython 需要 numpy、scipy、SoundCard、pywinpty；这些是验证依赖，不是应用运行依赖。

```powershell

$env:PYTHONPATH = Join-Path $PWD 'build\latency-deps'
$env:PYTHONIOENCODING = 'utf-8'
```

必须使用新的 `--name`，避免覆盖原始数据。`--baseline` 使用保存的替换前宿主和测量二进制。正常测量使用 `target/debug/thmr.exe tui` 和 `target/debug/thmrd.exe`，独立配置和运行目录，不改正常用户设置。仅显式开启测量时记录 PCM 和位置日志，不记录授权头或电台 URL。

主要本地证据在 `build/latency/`：

- `before-replacement/`：替换前二进制、解码分析源码和宿主源码备份。
- `before-fresh1/`、`before-controlled/`：本次替换前复测。
- `production-source1/`、`production-source2-final/`、`production-lifecycle-final/`：采用的正式复测及各代次的 `analysis.json`。
- 各正式测量的 `host/epoch-*/` 保存源 PCM、解码、取用和单次请求记录；根目录保存系统输出、设备时间戳、TUI 帧提交、接收的指标帧、命令事件与进程资源。

一轮音源 2 和初次生命周期采集缺少源 PCM 证据，调整可选记录初始化的先后次序后重新采集。`production-source2/` 与 `production-lifecycle/` 未计入上述 100 片段和 241.44 秒；数据保留以供审查。

测量边界仍是 WASAPI 输出端点到终端帧提交，未测屏幕扫描、设备无线链路或声学路径。若按 FFT 窗口中心定位内容，各项时差加约 23.22 ms。尚未测量 Release、长时间漂移以及 macOS/Linux 的真实音频行为。本次未发布安装包；提交记录以 Git 历史为准。
